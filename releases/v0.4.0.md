# Donjon Agent 0.4.0

This release lets the runtime run as a Doer agent through Doer's built-in `process` adapter, without changing Doer. The integration is optional and off unless four `DOER_*` environment variables are set.

## Included

- Doer client and on-switch (`DOER_API_URL`, `DOER_API_KEY`, `DOER_COMPANY_ID`, `DOER_AGENT_ID`; environment only).
- Startup check: the Doer run ID becomes the request ID; wake context is read from the run; work from a cancelled run is not resumed.
- Approval tools backed by Doer's approvals, with no local approval list and no tool to approve, reject or request a revision.
- Issue tools for the heartbeat procedure in Doer's skill.
- Cost reporting to Doer after each run.
- Known credentials are removed from tool arguments in the action journal.

## Upgrade and compatibility

No migration. Agent homes and execution state from 0.3.0 work unchanged, and behavior without the Doer variables is the same as 0.3.0, with one difference: tool arguments in the action journal now have known credentials replaced by `[REDACTED]`. Execution recovery, request deduplication, exclusive ownership, cancellation and exports are preserved.

Install the downloaded archive with `npm install -g ./donjon-agent-0.4.0.tgz` after verifying SHA256SUMS. Setup for Doer is in DOER.md.

## Limitations

- Tested against a fake Doer API only. Not yet run against a real Doer instance, and not run on Windows.
- Doer approvals are a workflow record, not a security boundary, on a default (`local_trusted`) Doer install. Keep the shell switch off for agents whose approvals must mean something.
- If Doer is unreachable at start, request deduplication is off for that start and a cancelled run cannot be recognized.
- Shell and API effects are not exactly-once.
